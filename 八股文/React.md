## 1.面试如何阐述:在 react 中组合优于继承?

组合是实现代码复用和构建灵活逐渐结构的首选
react 组件本质上更像函数,组合更加符合这种模式
避免传统继承可能带来的成绩过深,方法覆盖混乱的问题
不否定继承的价值,只是在 react 哲学中,组合更有优势
react 的设计哲学和组件模型本身更倾向于组合
组件间的关系更多是包含和使用,而非派生
所以优先考虑组合

## 2.react 的错误边界 ErrorBoundaries

错误边界避免整个应用因局部错误而白屏或者崩溃
提供友好的错误提示,引导用户
增强应用健壮性,隔离错误,防止错误蔓延
便于错误追踪和修复,可以在错误边界中集成错误上报机制

## 3.如果让你设计一个组件库,你会考量哪些因素?

-1.一致性:要确保用户在不同模块所看到的视觉风格,交互行为是统一的
-2.可复用性: 减少重复代码, 提高开发效率
-3.高效性:快速搭建高质量的界面
-4.可维护性:易于理解,修改和扩展
-5.健壮性:组件行为稳定、可预测性
-6.视觉设计:设计规范,主题话能力,响应式设计
-7.API 设计清晰,可预测,最少暴露,遵循 html 标准
-8.events:命名一致性,参数明确
-9.slots/children:提供灵活的内容分发
-10.原则:简洁直观、易于学习、不易误用一样

## 6.如何做持久化存储?

localStorage:
数据永久存储,除非用户手动清除浏览器或者代码主动删除
同源下的所有标签页和窗口共享数据
容量较大(通常 5-10MB)

sessionStorage:
数据仅在当前浏览器会话期间有效, 关闭标签或浏览器后数据被清除
数据仅在当前标签内可见,不同标签页不共享
容量与 localstorage 类似

## 8.解释一下服务端渲染的工作流程和优缺点

ssr 核心: 服务器渲染整个 HTML, 利于 SEO 和首屏
工作流程: 请求=》服务端获取数据=》服务端渲染 HTML=》浏览器显示=》JS 注水
主要优点: SEO 友好, FCP 快
主要缺点: 服务器压力大, 开发部署复杂
应该根据项目 seo、首屏性能权衡
